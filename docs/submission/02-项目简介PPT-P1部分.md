## P1-1　系统总体架构

**页面要点**

- 一个中枢，四类能力：主后端承接前端交互，编排**出题算法 / 评估服务 / 知识库检索**三类 AI 能力
- 分层架构：接口层 → 业务层 → 适配层 → 数据层，职责单一、互不越界
- 技术栈：Python FastAPI（异步）· SQLAlchemy 2.0 异步 ORM · JWT 鉴权 · SQLite / MySQL 双支持
- 四个服务进程协同：主服务 8001 · 评估 8002 · 知识库检索 8003 · 演示前端 5273
- 异步 IO 与大模型调用天然匹配，支撑多学生并发面试

## P1-2　面试流程编排

**页面要点**

- **表驱动状态机**：待开始 → 进行中 → 已结束，非法转换一律拒绝，不产生脏数据
- 一场面试 = **1 道开场题 + 6 轮动态追问**，共 7 轮完整对话闭环
- 追问由考生回答质量驱动：分层深入，答不出则降级引导（能力由 P2 提供，流程由本模块编排）
- **出题即落库、作答再回填**：任何时刻中断都能无损恢复，不存在"有答案无问题"的脏数据
- 轮次上限、超时预算等全部参数可配置，无需改代码即可调整面试节奏

**配图建议**：横向流程条 —— 开始面试 → 第 1 轮开场 → 追问 2~7 轮 → 自动出报告；
下方叠加状态机三态流转箭头图；右侧用小字标注"全程可中断恢复"。

## P1-3　高可用集成保障（核心亮点）

**页面要点**

- **五级数据源降级链**：题库策略 → 语义检索 → 外部服务 → 大模型直连 → 内置兜底
- 任一级失败**自动落到下一级**，最后一级必然成功 —— **面试流程永不中断**
- **分档超时预算**：知识库检索 60 秒 / 评估服务 30 秒 / 通用调用 15 秒，按各服务真实耗时画像设定
- 健康探测带 120 秒缓存，避免每轮对话都重复探测拖慢响应
- 契约归一化校验：外部返回的评分必须齐全且落在合法区间，否则整体回退，**绝不把异常数据写进报告**

**配图建议**：五级阶梯式漏斗图（自上而下逐级降级），每级右侧标注触发条件与超时预算；
底部用醒目色块强调"永不中断"结论。

## P1-4　数据基座与知识库集成

**页面要点**

- 6 张业务表承载全流程数据：用户 · 面试 · 问答记录 · 评估报告 · 岗位 · 题库
- 题库落地 **5012 题 / 5 个技术岗位**（后端开发、前端开发、测试开发、算法工程师、系统设计工程师）
- 题目结构化 19 个字段：基础与进阶得分点、三级追问、降级策略、单题校准锚点等
- 知识库 **74011 条向量条目**，两段式检索（语义召回 + 精排），支持选题与展开两种模式
- **导入流水线幂等可回滚**：支持预检模式、重建前自动备份、非法数据跳过并汇总告警

（源数据 → 校验映射 → 入库），右侧标注知识库向量条数与检索模式。

## P1-5　工程化与质量保障

**页面要点**

- **68 项自动化测试用例**，全量运行约 7 秒；测试库自动隔离，不污染开发数据
- **2000 场流程仿真**（5 岗位 × 400 场）验证算法效果：兜底 0 次、收尾题 100% 出现
- 数据库并发优化：写前日志模式 + 忙等超时，多场面试并发提交不锁库
- **一键启动**：单条命令拉起全部服务，就绪探测 + 进程存活监控 + 退出时统一回收，零残留
- 演示前端随之自动就绪，**评委可零配置直接体验完整流程**
