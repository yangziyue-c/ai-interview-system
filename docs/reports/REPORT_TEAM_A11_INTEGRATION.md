# A11 AI 对话层集成 · 团队汇报

> 面向 P1~P5 全体。对接细节见两份专项文档：`REPORT_TO_P5_A11_INTEGRATION.md`（给 P5）、
> `REPORT_TO_P4_A11_ENGINE.md`（给 P4）。用法与排障见 `backend/dialogue_layer/README-集成说明.md`。

## 一句话

P5 交付的 A11 AI 对话层已作为**可选面试引擎**接入主项目：出题、追问、五维评分可以整场委托给它，主后端负责把每轮问答与报告写回自己的数据库，历史、成长曲线、学习计划、报告分享都不受影响。默认关闭，配置一个开关即可启用。

## 一、这次做了什么

主后端现在有两条面试链路，由 `interviews.engine` 标记，**开场时定死、整场只读**：

```
                        ┌─────────────────────────────┐
  演示前端 5273 ───────▶│  主后端 8001                 │
                        │  原链路：题库策略 + P3 评估    │──▶ 8002 评估服务
                        │  引擎链路：适配器 + 镜像落库   │──▶ 8005 AI 对话层
                        └─────────────────────────────┘         （P5 的 A11）
```

| 项 | 原链路（默认） | 引擎链路 |
| :--- | :--- | :--- |
| 出题与追问 | 题库策略（`interviewer_new/`） | 对话层内部（判档融合、复读守卫、换题出路、难度自适应、KG 避重） |
| 评分 | P3 评估服务（8002） | 对话层内部（逐轮 LLM 五维评分） |
| 题量 | 7 轮（1 开场 + 6 追问） | 10 题（3/5/2 阶段） |
| 数据落库 | 直接写主库 | 主后端镜像写主库（形状与原来一致） |

代码位置：对话层在 `backend/dialogue_layer/`（P5 的代码一行未改），主后端新增适配器 `app/adapters/ai_dialogue.py` 与报告换算 `app/core/engine_report.py`。

## 二、怎么用

```bash
# 1. 模型权重（约 2.27GB，只下一次）
cd backend
pip install modelscope
python -c "from modelscope import snapshot_download as d; \
  d('BAAI/bge-reranker-v2-m3', local_dir='.hf_cache/bge-reranker-v2-m3')"

# 2. 配 DeepSeek 密钥：backend/.env 里的 LLM_API_KEY
# 3. 启用引擎：backend/.env 里设 DIALOGUE_ENGINE=a11
# 4. 照常一键启动（对话层由 start.py 自动拉起，端口 8005）
```

不设 `DIALOGUE_ENGINE` 时行为与今天完全一致，所有服务照常启动（8005 也会起来，只是面试不走它）。

## 五、已知边界

- **两种链路的分数不可直接比较**：原链路按题注入校准锚点，对话层逐轮 LLM 打分。成长曲线已带 `engine` 字段并支持按链路筛选，前端暂未接入。
- **对话层未就绪时不回落**：引擎模式下若 8005 不可用，面试接口明确返回 503（50300），不会静默换回原链路。这是刻意的，避免分数口径中途变化而事后无法分辨。
- **对话层的会话在内存里**：TTL 2 小时、容量 200 场；服务重启会丢会话，但主后端已镜像落库，已答内容不丢。
- **RAG 保持关闭**：本机整机内存 15.2 GB，低于对话层文档建议的「开 RAG ≥16 GB」门槛；三件数据已备好，将来改一个环境变量即可开。
- **未验证**：对话层文档里那两条欠账（判档真超时的耗时行为、9 场对照重跑）仍未补，需要 API key 与独占 8005 的时间窗口。
