# 《深镜智聘》项目简介 PPT 核对意见

本文逐页核对了《深镜智聘.pptx》（34 页）中的数字、技术表述与页面内容，以项目仓库的代码和实测为准。列出建议修改项，供修订参考。

核对时间：2026 年 10 月 9 日。

---

## 一、必须修改

### 1. P8 技术栈：删掉「Pinia」

技术栈一行现为：

> 前端：Vue3 + Vite + ECharts + Vosk-Browser + **Pinia** + Axios

前端实际未引入 Pinia。可改为：

> 前端：Vue3 + Vite + ECharts + Vosk-Browser + Axios

如需保留状态管理这一信息点，可参照 10.8 版方案文档的写法补一句：「全站共享状态采用轻量方案，在 auth.js 中导出全局 ref，各页面引用同一份数据，无需引入 Pinia 或 Vuex」。

### 2. P28 与 P17 的测试用例数：169 → 180

P28「三层验证」第一项现为：

> 单元与接口测试 169 项（单元 66 + 接口 103）

实测在主后端目录运行 `python -m pytest -q`，结果为 **180 passed**。逐文件明细如下，供按原有口径重新划分时参考：

| 文件 | 实测项数 |
| :--- | :--: |
| test_api.py | 41 |
| test_question_bank.py | 37 |
| test_resume_fields.py | 28 |
| test_resume_api.py | 23 |
| test_dialogue_engine.py | 28 |
| test_study_plan.py | 16 |
| test_evaluator_new.py | 7 |
| **合计** | **180** |

「单元 66 + 接口 103」这组细分与现状对不上（差额集中在 test_api.py 与 test_dialogue_engine.py，共 +11 项），建议按你们自己的单元/接口划分重新统计，总数写 180。

P17 末尾「验证体系：冒烟测试 2824 项通过，单元测试 66 项」中的「单元测试 66 项」同属这批旧数字，请一并核对。若此处指的是对话层引擎自身的单元测试，建议在页面上写明归属（如「对话层引擎单元测试 66 项」），避免与主后端的 180 项混淆。

### 3. P29 中间四块内容与 P28 重复：整块删除

P29（数据安全与隐私保护）页面上有八块内容，其中四块与 P28 一字不差：

- 造数工厂：合理默认值 + 随机后缀，绕开唯一约束，独立于 conftest.py
- 功能测试结果：冒烟 2824 项 0 失败；质量链 0 错误；五岗位原题 150 条；扩展验证 500 题/2000 回答；摄像头基准 11/11
- 流程仿真硬判据：兜底题库调用 0 次；收尾题出现 ≥200 次；曾定位 V5 追问触达率 66% 退化，改为语义分流后恢复 100%
- 性能测试：异步框架匹配外部调用耗时；超时分档——知识库 60s、评估 30s、常规 15s；WAL + 忙等 30s 支持并发写入

这四块属于「测试体系」，P28 已经完整呈现，P29 上的应为复制 P28 时残留，建议删除。删除后 P29 保留：鉴权与口令、越权防护、上传安全，以及右侧的鉴权与越权防护流程图。

可考虑补充：10.8 版方案文档的数据安全一节共五个方面，P29 正文目前只有前三项，另两项（简历文件私有存储、对外分享）仅在流程图中出现。是否补成正文卡片，按版面情况定。

## 二、建议核对

### 4. P4「AI 招聘预算占比约 36%」与方案文档的 35% 不一致

P4「市场增长」卡片写「AI 招聘预算占比升至约 36%」，而 10.8 版方案文档 11.2.1 写的是「AI 面试在 AI 招聘中的预算占比亦从约 29% 提升至约 35%」。同一套材料两处数字不同，请核定数据来源后统一。

### 5. P23 与 P24 内容重叠

两页都是知识图谱：图谱结构（14522 节点、56308 边、1340 知识点）、节点与边的类型、has_kp 加权规则在两页各出现一次，重叠约六成。建议合并为一页，或让 P24 只保留「知识图谱组成及应用」流程图与表格中不重复的部分。

## 三、清理项

### 6. P2 有一段隐藏的残留文本

P2 的页面数据里存着「编写技术文档与使用手册」这一句，来自分工表的表述。它在放映与转 PDF 时都不显示，但他人接手编辑或转换格式时可能露出来，建议在 PPT 中定位后删除（可用「开始 → 查找」搜索该句）。
