# 对话层接口 × 本项目接口 · 对照表（给 4 号）

> 这份单独成文，专治一件事：**P5 交付的前端包里那三个页面，不能照抄。**
> 它们调的是「AI 对话层」自己的接口，与本项目的对外接口是**两套**。
> 本文只讲「哪两套、怎么对应、差在哪」；引擎模式的完整说明见
> `REPORT_TO_P4_A11_ENGINE.md`，本项目对外接口的权威始终是 `docs/API.md`。

## 一、为什么会有两套

| 那套 | 跑在哪 | 谁在用 |
| :--- | :--- | :--- |
| **对话层接口** | 独立服务，端口 **8005**（`backend/dialogue_layer/`，由 `start.bat` 拉起；正式环境由 P5 运行，本项目经 Tailscale 连它） | 对话层自带的调试页（`web/*.html`）；本项目**主后端在内部**调它 |
| **本项目接口** | 主后端，端口 **8001** | **前端应该接的就是这一套**——它是唯一的对外面 |

主后端在中间做了一层转换：前端调它，它再调对话层，然后把结果按本项目的形状回给前端。
所以**前端的请求/响应形状一个字都不用照对话层的来**，尤其注意 `/chat`——对话层那侧是 SSE 流，
主后端已经把它消费掉了，对外就是普通的 JSON 响应。

## 二、逐条对照

| 对话层（8005） | 本项目（8001） | 说明 |
| :--- | :--- | :--- |
| `POST /start` | `POST /interviews` | 建会话；对话层那一跳由主后端替你调 |
| `POST /next` | —（**无直接对应**） | 下一题由 `POST /interviews/{id}/answers` 响应里的 `next_question` 带回，不需要单独要 |
| `POST /chat`（**SSE**） | `POST /interviews/{id}/answers` | 主后端内部消费 SSE，**对外是普通 JSON**，前端不需要 `EventSource` |
| `POST /finish` | `POST /interviews/{id}/finish`（或答满自动结束） | |
| `GET /result/{session_id}` | `GET /reports/{interview_id}` | **口径不同**：对话层 0-5，本项目 0~100 |
| `POST /asr` | `POST /uploads/audio/asr` | 一次调用同时给文本与可直接提交的 `url` |
| `POST /tts` | `POST /uploads/audio/tts` | 返回**本站**音频地址（不是对话层那台的） |
| `POST /body-language/analyze` | `POST /body-language/analyze` | 请求/响应同形（都是本地关键点进、姿态信号出） |
| `POST /growth` | `GET /reports/archive` | 成长档案：错题本 / 考点地图 / 历史成绩 |
| `POST /practice` | —（**未接**） | 要做「专项练习」界面时再一起接 |
| `POST /model_answer` | —（**未接**） | 同上；接入时记得渲染 `note`（见下） |
| `GET /health` | `GET /health` | 本项目自己的健康检查，与对话层无关 |

**本项目另有、对话层没有的一大片**（这些是正式前端的主力）：认证与个人资料、岗位列表、
面试历史与详情、题库查询、简历上传与下载、报告分享、学习计划、复盘清单。
完整清单看 `docs/API.md`。

## 三、四处理念差异

这是「为什么不能照抄」的根子：

| 维度 | 对话层 | 本项目 |
| :--- | :--- | :--- |
| **鉴权** | 无 | 全部要 `Authorization: Bearer <token>`；免登录的只有注册、登录、岗位列表、分享报告四个 |
| **会话** | `session_id`，**存在内存里**，服务一重启就全丢 | `interview_id`，落数据库；历史、成长曲线、分享都靠它 |
| **刷新恢复** | 页面刷新即丢（会话 ID 只在 JS 变量里，也没调 `/result` 去恢复） | 用 `interview_id` 可以恢复（`GET /interviews/{id}`） |
| **五维分数** | 0-5，步进 0.05 | **0~100** |

## 四、那三个调试页里容易踩的地方

| 页面 | 坑 |
| :--- | :--- |
| `test_chat.html` | 直连 8005、调对话层接口；分数按 0-5 显示；`session_id` 只放 JS 变量，**刷新页面这场面试就断了且找不回** |
| `resume_setup.html` | 把简历存进浏览器 `localStorage`，**不落任何服务器**（换机器或清缓存即丢）。本项目另有 `/resumes` 一套接口，简历是落服务端的，正式前端要用那一套 |
| `body_camera.html` | 只管采集与调用分析接口，不涉及流程——它的实现（浏览器本地提关键点、画面不出本机）是可以参考的 |

另外一条与接口无关但要记住的：对话层的参考答案里，`kind` 为「示范作答」的那 991 篇，
正文是照 STAR 骨架编的**通用示例**、不是真题范文。接入 `/model_answer` 时，
**必须把同一条返回里的 `note` 渲染出来**——不显示 note，考生会把虚构经历当范文背下去。
