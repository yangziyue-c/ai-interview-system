# A11 对话层引擎模式 · 前端对接说明（给 4 号）

> 补在 `REPORT_TO_P4.md` 之后。**结论先给：前端不需要改任何代码，已冻结的契约没有被打破。**
> 这一份只讲三处新增的字段与一处要处理的错误码；接口细节以 `docs/API.md` 为准。

## 一、引擎模式是什么

后端接入了 P5 交付的「AI 对话层」（独立服务，端口 8005）。它在后端 `.env` 里由 `DIALOGUE_ENGINE=a11` 开关：

| 开关 | 面试怎么跑 |
| :--- | :--- |
| 留空（**默认**） | 本项目原链路：7 轮制，题库策略出题，P3 评估出报告 |
| `a11` | 委托对话层：**10 题制**，出题、追问、五维评分都在 8005 内完成，主后端把每轮问答与报告镜像写回自己的库 |

开关是**部署级**的，改一处影响所有人（不是按用户或按场次）。切换后新开的场次走新模式，历史场次不受影响。

**对你最关键的一条**：主后端自己消费 8005 的 SSE 流，**对外的接口形状一个字没变**。提交答案仍然是普通 JSON（`finished` / `next_question` / `report`），不需要 `EventSource`、不需要 `fetch` 流式读取。`REPORT_TO_P4.md` 里把「误以为提交答案是 SSE」列为致命错误第 1 条，这条现在依然成立。

## 二、契约的三处加法

都是新增字段或可选参数，不传、不读都不影响现有实现。

### 1. `GET /config` 多一个 `engine` 字段

```json
{ "code": 0, "message": "ok", "data": {
  "total_rounds": 10,
  "max_follow_up_rounds": 6,
  "engine": "a11"
} }
```

- `engine`：`"standard"` = 原链路，`"a11"` = 引擎模式。可以拿它做文案（比如提示「本场由 AI 对话层主持」）。
- `total_rounds`：引擎模式下是 **10**（对话层固定 10 题），原链路仍是 7。你已经在按这个字段渲染「第 N / 共几题」，所以**不需要改动**；只是会看到分母变成 10。

### 2. `GET /reports/growth` 每项多一个 `engine` 字段

```json
{ "interview_id": 3, "position": "backend", "engine": "a11", "finished_at": "...",
  "total_score": 84.5, "tech_score": 84.5, ... }
```

`engine` 为 `""` 表示该场是原链路评的，`"a11"` 表示引擎评的。

同时加了可选参数 `?engine=standard|a11`（不传 = 全部，行为与今天一致）。两种链路的五维分**不是同一把尺子**（原链路按题注入校准锚点，引擎逐轮 LLM 打分），混在一条曲线上会被误读成涨跌。将来做筛选时后端已就位；现在不做也没关系。

### 3. 新错误码 `50300`

引擎模式下，如果对话层没就绪或中途挂了，面试相关接口会返回：

```json
{ "code": 50300, "message": "AI 对话层未就绪（评分模型未就绪）……", "data": null }
```

HTTP 状态码是 **503**。请把它和 500 分开处理：这不是「后端崩了」，而是「依赖服务暂时没准备好，稍后重试」。建议文案类似「服务暂时不可用，请稍后重试」，并把 `message` 里的原因显示出来（它已经写成人话，例如「连不上对话层服务」「评分模型未就绪」「未配置大模型密钥」）。

注意：这只在引擎模式下出现。原链路（默认）不会有 50300。

## 三、引擎模式下你会看到的行为差异

| 现象 | 说明 |
| :--- | :--- |
| 一场问 10 题 | `total_rounds` 从 `/config` 拿，别写死 |
| 追问期间「第 N 题」不变 | 对话层的追问不推进题号，`current_round` 保持不动是**正确**的 |
| 追问文本照常下发 | 追问作为 `next_question` 返回，按现有逻辑渲染成一条 AI 消息即可 |
| 报告三栏仍然有内容 | `strengths` / `weaknesses` / `suggestions` 由后端从引擎明细推导，形状与现在一致 |
| 问答记录回看 | `GET /interviews/{id}` 的 `qa_records` 每题一行，题面是题库原题，与现在一致 |

## 五、第三版追加（2026-09-25）

对话层换了新版（端点 6 → 10），本项目对外**新增两个接口**，可择机接入；已有的契约仍然一个字没变。

### 5.1 `POST /uploads/audio/asr` 语音转写

```
POST /uploads/audio/asr    multipart/form-data，字段名 file
```

返回转写文本、表达指标，以及可直接提交的 `url`：

```json
{ "code": 0, "message": "转写完成", "data": {
  "text": "线程的状态包括新建、就绪、运行、阻塞和终止……",
  "url": "/uploads/12_ab3f9c2d.webm",
  "duration_ms": 16878, "audio_ms": 16878, "segments": [ ... ],
  "pauses": 0, "pause_total_ms": 0, "elapsed_ms": 3804,
  "loudness": 0.0622, "loudness_cv": 0.331, "tail_ratio": 1.05,
  "emotion": null, "emotion_score": null, "emotion_dist": null,
  "asr_model": "faster-whisper-…(int8)"
} }
```

要点：

- **一次调用同时给文本与地址**，同一个文件不用传两次；`url` 直接填提交答案的 `audio_url`。
- 转写有错字是正常形态（模型 small + int8）：把文本填进输入框、**让考生改**后再发送。
- `emotion*` 三项本部署恒为 `null`；`loudness*` 与 `tail_ratio` 是音量三指标，与情感无关。
- 引擎未就绪时返回 **503（50300）**，提示语是「语音转写不可用：…」。**不要当空文本处理**，那会被当成「考生没说话」。

演示前端（`frontend_test/js/audio.js`）已切到这个流程：松开话筒就上传转写，文本填进输入框，地址存在 `Voice.result.url` 供提交时复用。你的正式前端可以参考它的用法，也可以自行决定交互。

### 5.2 `GET /reports/archive` 成长档案

错题本 / 考点地图 / 历史成绩 / 提升路径，按岗位聚合（`?position=`，不传则取最近一场的岗位）。只有引擎链路评的场次才有档案；**没有档案或引擎不可用时返回 `available:false` + `notice`，不是错误**，界面照 notice 提示即可。

### 5.3 还没接的

对话层的「专项练习」与「参考答案」尚未接到主后端接口，等你要做对应界面时再一起接。

`review`（复盘清单）已经在 2026-09-26 接好了：它随 `GET /reports/{id}` 的 `review` 字段返回，契约见 `docs/API.md` 的 4.7 节；演示前端的报告页也已经渲染成「考后复盘」卡片，可以直接参考它的写法。

### 5.4 对话层给的硬要求（原样转达）

1. **请求超时不能设短**：对话层在外部大模型偶发卡住时**不返 5xx**，而是把超时预算跑完再收尾。所以前端的请求超时必须 **`/chat` ≥540 秒、`/finish` ≥360 秒**（整场最坏约 900 秒）。已归档实测是 `/chat` p50 3.1 秒 / p90 7.0 秒 / 最坏 25.2 秒——540 是兜底上限、不是常规耗时，但低于它会让正常场次被前端自己掐断。
2. **`kind` 为「示范作答」时，`note` 必须渲染**：参考答案里那 991 篇的正文是照 STAR 骨架编的**通用示例**，不是真范文。不显示 `note`，考生会把虚构经历当范文背下去。这条适用于 `/model_answer`（尚未接入），接入时一并做。
3. **`review` 已经接好了（2026-09-26）**：你不需要调对话层，直接读 `GET /reports/{id}` 返回里的 `review` 字段即可，契约见 `docs/API.md` 4.7 节。演示前端的报告页已经渲染成「考后复盘」卡片（漏点带 `advice`、下一步用 `actions[].text`、底部展示 `caveats`），文案都已由后端拼好，直接展示即可；`gaps` 为空时不显示那一组。
