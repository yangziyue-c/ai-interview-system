## 一、你的数据在整个系统中的位置

```
backend/rag/数据/{岗位}-v5.json（V5，18 字段）         ← 你负责生产/维护
        │  后端命令导入（幂等，可反复重跑）
        ▼
questions 表（数据库，5012 题 / 5 岗位）
        │
        ├─→ GET /api/v1/questions（题库浏览/筛选接口，见 docs/API.md）
        ├─→ P2 面试官出题：开场题 / 追问 / 收尾题按 岗位 + 阶段 + 难度 + 题型 抽题
```

## 二、V5 数据规范（18 字段，硬性要求）

### 2.1 文件形态

| 项 | 要求 |
| :--- | :--- |
| 存放目录 | `backend/rag/数据/`，文件名 `{前缀}-v5.json`（5 个前缀见上表） |
| 格式 | JSON 数组，每个元素是一道题的对象；UTF-8 无 BOM |
| 键名 | 中文键名，逐字一致（见 2.2）。写错键名不会报错，该字段会静默为空 |
| 条目数 | 导入脚本按「文件内每一条 = 一道题」处理，不再有 sheet / 表头概念 |

### 2.2 18 个字段（键名逐字一致）

| # | 字段名 | 填什么 | 入库列 | 必填 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | `题目ID` | 岗位内唯一的原题 ID，格式 `{岗位前缀}-Q{4位数字}`，如 `JAVA_BACKEND-Q0001` | `question_no` | ✅ |
| 2 | `所属岗位` | 岗位全名（见第一节表，必须逐字匹配） | `position_code`（经映射） | ✅ |
| 3 | `题型分类` | 受控词表 4 类（见 2.3） | `category` | ✅ |
| 4 | `难度等级` | `easy` / `medium` / `hard` | `difficulty` | ✅ |
| 5 | `面试阶段` | 受控词表 3 个（见 2.3） | `interview_stage` | ✅ |
| 6 | `考点优先级` | 受控词表 3 个（见 2.3） | `exam_priority` | ✅ |
| 7 | `题目内容` | 题干正文。可读性好、自包含，会被直接朗读给候选人 | `question` | ✅ |
| 8 | `核心关键词` | `JVM / JDK / JRE` 这类，供检索与选题参考 | `keywords` | 建议 |
| 9 | `基础得分点` | 多行文本，答出即达标的要点 | `basic_score_points` | 建议 |
| 10 | `进阶得分点` | 多行文本，答得好才覆盖的要点（P3 评分素材） | `advanced_score_points` | 建议 |
| 11 | `L1基础追问` | **两行结构**：`[触发] 条件` + 换行 + `[追问] 文本` | `follow_up_l1` | ✅ |
| 12 | `L2递进追问` | 同上（L1 答得好才走到这里） | `follow_up_l2` | ✅ |
| 13 | `L3拓展追问` | 同上（可含额外 `[触发]` 元信息行，算法取最后一个 `[追问]` 行） | `follow_up_l3` | ✅ |
| 14 | `降级策略` | 考生答不出时的引导话术（一段文本） | `fallback_strategy` | ✅ |
| 15 | `单题校准锚点` | **P3 判分标准**：`[技术水平] …` / `[岗位匹配度] …` 逐维度写"答到什么程度算好" | `calibration_anchor` | ✅ |
| 16 | `建议用时(分)` | 整数，如 `2`（仅参考，与后端轮次无关） | `suggested_minutes` | 建议 |
| 17 | `适用题型基准` | 同 `题型分类` 的值（数据生产端保留字段，不落库） | — | 选填 |
| 18 | `关联知识点` | `|` 分隔的知识点链路，如 `java-backend-kp-3180|JVM入门与体系结构|…` | `related_knowledge` | 选填 |

> **`stage_order`（阶段顺序）不用你写**：导入脚本由 `面试阶段` 自动派生
> （`开场热身`→1 / `核心考察`→2 / `深度压轴`→3）。

### 2.3 受控词表（错一个字符就整条跳过，全角/半角与空格都敏感）

| 字段 | 合法值 |
| :--- | :--- |
| `题型分类` | `技术知识题` / `场景应用题` / `项目经历题` / `行为素质题`（4 类） |
| `难度等级` | `easy` / `medium` / `hard` |
| `面试阶段` | `开场热身` / `核心考察` / `深度压轴`（3 个） |
| `考点优先级` | `常规题` / `高频必考题` / `拓展题`（不校验，见下） |

> **上表只有前三项会被导入脚本校验**（`_VOCABULARY`）：写错会整条跳过并计入
> 「校验失败明细」。`考点优先级` 不做校验，写错不会跳过，而是原样入库形成静默脏数据
> （与第四节「只校验 4 类问题」口径一致）。

> **两处易错的词表变更**（V4 → V5，照旧写会整条丢题）：
> - 题型：`技术知识`→`技术知识题`、`行为面试`→`行为素质题`（V4 的 6 类收敛为 4 类）
> - 阶段：`深度考察`→`深度压轴`；`收尾交流` 已取消（收尾题现在按 `题型分类=行为素质题` 抽取）
>
> 词表的代码事实源是 [backend/app/models/question.py](../../backend/app/models/question.py)，
> 由 P1 维护；你只需要让 JSON 里的值属于上面清单。

### 2.4 追问字段的写法（算法直接读，必须两行结构）

```json
"L1基础追问": "[触发] 答出基础得分点、回答基本正确时触发\n[追问] 你提到了JVM，能具体说说它的定义和核心作用吗？"
```

- **`[触发]` 行**：写触发条件（描述式即可，算法不解析它的具体措辞）
- **`[追问]` 行**：写实际问出去的话
- **算法取的是最后一个 `[追问]` 行**：L3 常见写法是前面先写一行 `[触发] 本题为 easy
  难度，一般不触达 L3…` 的元信息，再写真正的触发条件，这种写法允许使用，算法也支持。

## 三、导入：把 JSON 变成 questions 表

### 3.1 运行命令（唯一入口）

> 必须在 `backend/` 目录下运行，且用 `-m`（直接 `python scripts/xxx.py` 会因
> sys.path 找不到 app 包而失败）；用 conda 环境里的 python.exe。

```bash
cd backend

# 先空跑看统计（不落库，强烈建议改完先跑这个）
D:/anaconda3/envs/ai_interview/python.exe -m scripts.import_question_bank --dry-run

# 确认无误后正式导入（幂等：按 (岗位, 题目ID) 更新或新增）
D:/anaconda3/envs/ai_interview/python.exe -m scripts.import_question_bank

# 表结构变更时（如加字段/删字段）——会先 VACUUM INTO 自动备份，再重建表
D:/anaconda3/envs/ai_interview/python.exe -m scripts.import_question_bank --rebuild --yes
```

> conda 环境实际路径以 `conda env list` 为准；本机 `conda run` 有插件 bug，请直接调用 python.exe。

### 3.2 成功输出长这样

以下为 `--dry-run` 实测输出（真跑时末段为「✅ 导入完成：5 个文件，新增 N 题，更新 M 题」）：

```
============================================================
题库导入：backend/rag/数据/*-v5.json → questions 表
源目录：backend/rag/数据
============================================================
解析到 5012 条记录（5 个文件）

✅ 解析完成（--dry-run 未落库）：可导入 5012 题
   岗位分布：algorithm 655 / backend 2146 / frontend 734 / system_design 810 / test_engineer 667
   阶段分布：开场热身 1782 / 核心考察 2800 / 深度压轴 430
   校验失败跳过：无
```

### 3.3 幂等：可放心反复跑

- 按 `(岗位, 题目ID)` 复合键匹配：已存在 → 更新；不存在 → 新增。
- 跑两遍验证：第二遍应是 `新增 0 题`（全部命中更新分支）。
- **改完 JSON 直接重跑即可**，旧字段被新值覆盖。

## 四、验证入库成功

1. **看导入输出**：各岗位题数与预期一致、`校验失败已跳过` 为空。
2. **接口验证**（任选）：
   - Swagger `http://localhost:8001/docs` → 登录后调 `GET /questions`；
   - 或 curl：`GET http://localhost:8001/api/v1/questions?position=algorithm&category=项目经历题&limit=5`
     （带 `Authorization: Bearer <token>`）。
3. **面试实测**（可选）：双击 `backend/start.bat` 后打开 `http://localhost:5273`（演示前端），
   跑一场对应岗位的模拟面试，确认开场题/追问来自你的新题。

> **改了数据还要重建向量库**：RAG 检索用的是 `backend/rag/vector_db/`（由 `代码/01`→`代码/02`
> 从同一份 JSON 生成）。只改 JSON 不重建，语义检索仍是旧内容；重建命令与耗时见
> `backend/rag/代码/README.md`（CPU 约 3~7 小时，支持断点续跑）。

## 五、导入告警对照表

**先说清楚边界**：导入脚本只校验 4 类问题（下面表格前 3 行 + 重复题号）。
其余字段写错键名或缺值，一律静默为空、不会告警，所以改完务必跑 `--dry-run` 并抽查几条。

| 输出 | 含义 | 处理 |
| :--- | :--- | :--- |
| `缺题目ID` | 该条没有 `题目ID`（或为空） | 补上唯一 ID |
| `校验失败已跳过：{'题型分类=xxx': n, ...}` | 值不在受控词表（常见：照 V4 写「技术知识」而非「技术知识题」、写了已取消的「收尾交流」、前后带空格） | 按 2.3 改 |
| `校验失败已跳过：{'岗位=xxx': n}` | `所属岗位` 不是全名（常见：写成 V4 简名「Java后端」、少一个空格） | 按第一节表逐字核对 |
| `⚠️ 重复题号（本批次覆盖）：…` | 同一文件里 `题目ID` 重复 | 改成唯一（后出现的会覆盖先出现的） |
| **没有告警但字段是空的** | 键名写错（如 `L1追问` 写成 `L1基础追问`）或漏写 | 对照 2.2 逐字核对键名 |

## 六、新增一个岗位的完整流程（以「算法工程师」为例）

V5 下新增岗位涉及 5 个环节（1~3 找 P1，4~5 由你完成）：

1. **岗位开放**：positions 表启用该岗位（P1 操作）；
2. **评估权重**：《评估维度.csv》加该岗位一列 + `app/core/evaluation_weights.py` 的
   `POSITION_CONFIG` 同步（P1；跑 `tests/test_api.py::test_weights_match_csv` 机器校验）；
3. **岗位映射**：导入脚本 `POSITION_MAP` 加「全名 → code」（P1 操作）；
4. **数据文件**：你按本文第二节产出 `{前缀}-v5.json`，放入 `backend/rag/数据/`；
5. **导入 + 双验证**：`--dry-run` 看统计 → 正式导入 → 输出无 skipped →
   Swagger `GET /questions?position=<新code>` 确认。

> 若该岗位还需要 RAG 语义检索覆盖：再跑 `代码/01`→`代码/02` 重建向量库（找 P1 协同）。

## 七、约定与红线

| 事项 | 约定 |
| :--- | :--- |
| 改题后必须重跑导入 | 否则库里还是旧题，线上面试/评估用的不是你的新数据 |
| 不要手动改数据库 | 你的唯一入口是 JSON + 导入命令；手改下次导入会被覆盖或留下脏数据 |
| **所有文件改动都在 `backend/rag/` 下** | 不再有"交付包"环节；不要把数据放到仓库外或其他目录 |
| **向量库目录名保持纯 ASCII** | 现名 `vector_db/`，改名/移动都必须保证全 ASCII 路径（见文首铁律②） |
| 键名/词表/岗位写法 | 严格按本文，宁可不写也别写错一个字符（词表错值整条跳过；键名错值静默为空） |
| 多行文本 | `基础得分点` 等多行内容用 JSON 的 `\n` 转义即可，导入不拆分 |
| `题目ID` 风格 | 按岗位前缀 + `-Q` + 4 位序号：`JAVA_BACKEND-Q0001`、`ALGORITHM-Q0001` 等 |
| 内容口径 | 涉及岗位评估维度/流程规则的问题，以 docs/API.md、docs/DATABASE.md 与 `REPORT_TO_P2_INTERVIEWER_NEW.md` 为准 |

## 附录：V4（Excel）时代的历史说明（仅供理解演进，不要再照它操作）

2026-09-14 之前，题库以 `题库/*.xlsx`（16 列、含「面试题库」sheet）形式交付，
由导入脚本强校验表头后落库。该流水线已整体废止，原因与替代如下：

| V4 环节 | 现状 |
| :--- | :--- |
| `题库/*.xlsx` 目录 | 已删除（Git 历史仍可追溯） |
| 16 列表头强校验、sheet 名要求 | 取消（改为 JSON 数组 + 18 中文键名） |
| `大类` 6 类 / `面试阶段` 4 个（含「收尾交流」） | 收敛为 4 类 / 3 个 |
| 得分点 `【basic 0.3】…` 三段式 | 改为 `基础得分点` / `进阶得分点` 两列 |
| 追问挤在 `追问触发条件` 一列、需 119 行正则解析 | 拆成 `L1/L2/L3` 三列，格式 100% 规整、无需解析 |
| 参考答案 / 备注 / 优秀范例 / 表达评估要点 等 9 列 | 已删除（改为提供单题校准锚点与得分点） |
| 软技能标签自动剥离 | 取消（V5 数据不再带该标签） |

> 换代带来的收益：出题算法删掉了 119 行格式兼容代码，追问链触达率 66% → 100%。
> 若你手上还有 V4 xlsx 需要回看，请从 Git 历史取（`git log -- 题库/`）。
