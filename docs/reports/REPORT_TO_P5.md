# 致 P5（题库）同学：Excel 题库 → questions 表 操作手册

> 来自 P1（后端）。你在团队中负责整理/维护各岗位面试题库 Excel（仓库根目录 `题库/`，V4 版）。
> 本文档是 **Excel → 数据库 questions 表的完整操作手册**：xlsx 长什么样、怎么导入、
> 怎么验证、遇到告警怎么办、新增一个岗位怎么走全流程。
>
> 一句话总结你的工作流：**改 Excel → 放 `题库/` → 跑一条导入命令 → 完成**，
> 全程无需写任何后端代码；题库是「出题」「追问」「评估」的唯一数据源，格式正确性至关重要。

---

## 一、你的数据在整个系统中的位置

```
题库/*.xlsx（V4，16 列，含「面试题库」sheet）          ← 你负责生产/维护
        │  后端命令导入（幂等，可反复重跑）
        ▼
questions 表（数据库，451 题：backend 151 + frontend 150 + test_engineer 150）
        │
        ├─→ GET /api/v1/questions（题库浏览/筛选接口，见 docs/API.md）
        ├─→ P2 面试官出题：开场题 / 追问 / 收尾题按 岗位+阶段+难度 抽题
        └─→ P3 AI 评估：得分点 / 表达评估要点 作为评分素材
```

- 修改题库的生效路径：**改 xlsx → 重跑导入命令**，面试官与评估立刻用到新题，后端代码零改动。
- 你不需要碰 `interview.db`/MySQL 里的数据（导入脚本负责落库）；也不需要改任何 `.py`。

## 二、xlsx 文件规范（V4，硬性要求）

### 2.1 位置与命名

| 项 | 要求 |
| :--- | :--- |
| 存放目录 | 仓库根目录 `题库/`（文件名含「面试题库」或对应岗位名，参考现有 3 个文件） |
| Sheet 名 | 必须含 **`面试题库`**（导入脚本取该 sheet；缺了会整文件跳过） |
| 每行 | 一道题，表头占第 1 行 |

### 2.2 16 列表头（与现有文件**逐字一致、列序固定**）

导入脚本会**强校验**表头：列名或顺序与下表任何一处不符，立即报错拒绝整个文件（防字段错位入库）。
**不要**增删列、调换列序、改列名（哪怕加空格）。

| # | 列名（必须逐字一致） | 填什么 | 必填 |
| :--- | :--- | :--- | :--- |
| 1 | 题目编号 | 岗位内唯一编号，如 `tech_001` / `scene_012` / `code_003` / `project_001` / `behavior_001`（跨岗位可重复，每岗都有 tech_001） | ✅ |
| 2 | 所属岗位 | 中文名（见 2.3 岗位映射，**必须逐字匹配**） | ✅ |
| 3 | 大类 | 受控词表 6 类（见 2.4） | ✅ |
| 4 | 题目分类 | 细分分类，如 `Java基础` / `测试用例设计` / `CSS布局`（自由文本） | 建议 |
| 5 | 难度等级 | `easy` / `medium` / `hard`（受控） | ✅ |
| 6 | 面试问题 | 题干正文。**可读性好、自包含**，会被直接朗读给候选人 | ✅ |
| 7 | 得分点 | `【basic 0.3】…【core 0.5】…【advanced 0.2】…` 三段加权（合计 1.0），评分 Prompt 素材 | 建议 |
| 8 | 追问触发条件 | `【L1-触发追问】…【L2-递进追问】…【L3-极限追问】…【降级策略】…`，P2 追问生成的依据 | ✅ |
| 9 | 参考答案 | 完整参考答案（含采分点） | ✅ |
| 10 | 备注 | 选题参考，如「高频考点」 | 选填 |
| 11 | 面试阶段 | `开场热身` / `核心考察` / `深度考察` / `收尾交流`（受控） | ✅ |
| 12 | 建议用时(分钟) | 数字，如 `3` | 建议 |
| 13 | 阶段顺序 | 1~4（对应 11 列阶段） | ✅ |
| 14 | 替代回答方向 | `方向1：…方向2：…`，给候选人的其他展开路径 | 选填 |
| 15 | 优秀回答范例 | `【优秀回答特征】…` | 建议 |
| 16 | 表达评估要点 | V4 新增：沟通表达维度评分素材（条理性/术语准确/追问响应…） | 建议 |

### 2.3 「所属岗位」中文名 → 岗位 code 映射（导入脚本唯一入口）

| xlsx 里的写法（逐字一致，勿加空格） | 入库 position_code |
| :--- | :--- |
| `Java后端` | `backend` |
| `Web前端` | `frontend` |
| `软件测试开发` | `test_engineer` |

> 映射维护在导入脚本 `POSITION_MAP`。**加新岗位需找 P1 同步映射**（见第六节），
> 否则该文件的题全部进入 skipped 告警、不入库。

### 2.4 受控词表（大小写与全角空格敏感，错一个字符整行被跳过）

| 列 | 合法值（V4） |
| :--- | :--- |
| 大类 | `技术知识` / `系统设计题` / `场景题` / `编码与算法` / `项目深挖` / `行为面试` |
| 难度等级 | `easy` / `medium` / `hard` |
| 面试阶段 | `开场热身` / `核心考察` / `深度考察` / `收尾交流` |

> 历史教训：V4 之前大类叫「场景与设计」（现已拆为「系统设计题」+「场景题」），
> 旧文件若沿用旧大类会**整行跳过**。改动词表由 P1 在 `app/models/question.py` 维护，
> 你只需要让 Excel 里的值属于上面清单。

### 2.5 题干里的软技能标签（可留，导入时自动剥离）

题干若写了 `【岗位软技能考察：故障应急响应意识】`，导入脚本会自动把标签剥离到
`soft_skill_tag` 列，题干干净入库（候选人在对话里只会看到问题本身）。你可以不写，
写了也没关系，无需自己删。

## 三、导入：把 Excel 变成 questions 表

### 3.1 运行命令（唯一入口）

> ⚠️ 必须在 `backend/` 目录下运行，且用 `-m`（直接 `python scripts/xxx.py` 会因
> sys.path 找不到 app 包而失败）；用 conda 环境里的 python.exe（本机实测路径如下）。

```bash
cd backend
D:/anaconda3/envs/ai_interview/python.exe -m scripts.import_question_bank
```

> conda 环境实际路径以 `conda env list` 为准；本机 `conda run` 有插件 bug，请直接调用 python.exe。

### 3.2 成功输出长这样

```
题库导入：题库/*.xlsx → questions 表
✅ 导入完成：3 个文件，新增 0 题，更新 60 题
   剥离软技能标签：12 题
   backend: 151 题
   frontend: 150 题
   test_engineer: 150 题
```

### 3.3 幂等：可放心反复跑

- 按 `(岗位, 题目编号)` 复合键匹配：库中已存在 → **更新**该题；不存在 → **新增**。
- 跑两遍验证：第二遍输出应为 `新增 0 题`（全部命中更新分支），说明库与 xlsx 完全一致。
- 改了 xlsx 后想整体刷新某岗位：直接重跑即可，旧字段被新值覆盖。

## 四、验证入库成功

1. **看导入输出**：`per_position` 各岗位题数与预期一致；`skipped` 为空。
2. **接口验证**（任选）：
   - 浏览器打开 Swagger `http://localhost:8001/docs` → 需登录（`POST /auth/login`）后调 `GET /questions`；
   - 或 curl：`GET http://localhost:8001/api/v1/questions?position=backend&category=技术知识&limit=5`
     （带 `Authorization: Bearer <token>`）。
3. **面试实测**（可选）：双击 `backend/start.bat` 后浏览器打开 `http://localhost:5273`
   （演示前端），跑一场对应岗位的模拟面试，确认开场题/追问来自你的新题。

## 五、导入告警对照表（skipped 里出现这些就看这里）

| 输出/报错 | 含义 | 处理 |
| :--- | :--- | :--- |
| `ValueError: 表头与预期不符` | 表头列名/列序漂移，**整个文件被拒绝** | 对照 2.2 的表头逐字核对（含全角/半角括号、空格） |
| `skipped: 大类=xxx` / `难度等级=xxx` / `面试阶段=xxx` | 值不在受控词表（常见：旧版「场景与设计」、大小写写错、值前后带空格） | 按 2.4 修改 Excel |
| `skipped: 岗位=xxx` | 「所属岗位」不在 POSITION_MAP（常见：中文名/空格不一致，或新岗位未映射） | 核对 2.3 的写法；新岗位找 P1 加映射 |
| `skipped: 列数不符` | 某行不是 16 列（常见：末尾多空列、行内合并单元格） | 修正该行 |
| `⚠️ 重复题号（本批次覆盖）` | 同一文件里出现重复编号 | 编号改唯一（后出现的会覆盖先出现的） |
| `⏭️ 跳过（暂缓入库）：算法工程师面试题库 / 岗位知识点知识库` | 见下方「暂缓入库的两个文件」 | 无需处理 |

### 暂缓入库的两个文件（题库/ 里现成的，别删、别往里塞面试题）

| 文件 | 为什么暂缓 | 何时启用 |
| :--- | :--- | :--- |
| `算法工程师面试题库_155题_修复版V4.xlsx` | 岗位未开放（positions 表未启用 + 评估维度权重列缺失 + 脚本无映射） | 找 P1 按第六节流程启用 |
| `岗位知识点知识库_RAG_修复版V4.xlsx` | 无「面试题库」sheet，是知识点库（RAG 用），入库方案不同 | 等专门的知识库方案 |

## 六、新增一个岗位的完整流程（以「算法工程师」为例，找 P1 协同）

新增岗位不是只放一个 xlsx 就行，涉及 5 个环节：

1. **岗位开放**：positions 表启用该岗位（P1 操作，启动 seed 预留了岗位位）；
2. **评估权重**：《评估维度.csv》加该岗位一行 + `evaluation_weights.py` 同步（P1，跑
   `tests/test_api.py::test_weights_match_csv` 机器校验）；
3. **岗位映射**：导入脚本 `POSITION_MAP` 加「中文名 → code」（P1 操作）；
4. **题库文件**：你按本文 2.2/2.3/2.4 规范产出 xlsx，命名参考现成文件，
   放入 `题库/`（文件名与现有 `EXCLUDED_FILES` 关键字不冲突）；
5. **导入 + 双验证**：跑导入命令 → 输出无 skipped → Swagger `GET /questions?position=<新code>` 确认。

> 你只需要做 4 和 5 的验证；1~3 找 P1。启用期间临时把文件名改掉（避开 EXCLUDED 判断）
> 属于临时变通，正式做法是按上面流程走完后由 P1 从 EXCLUDED 移除。

## 七、约定与红线

| 事项 | 约定 |
| :--- | :--- |
| 改题后必须重跑导入 | 否则 interview.db 里还是旧题，线上面试/评估用的不是你的新 Excel |
| 不要手动改数据库 | 你的唯一入口是 xlsx + 导入命令；手改 interview.db 下次导入会被覆盖或留下脏数据 |
| 表头/词表/岗位写法 | 严格按本文，宁可不写也别写错一个字符（错值整行跳过，静默丢题） |
| 行内换行 | 得分点/参考答案等多段内容用单元格内换行（Alt+Enter）即可，导入不拆分多行单元格 |
| 编号风格 | 按岗位前缀：`tech_` / `scene_` / `code_` / `project_` / `behavior_`，便于阅读与统计 |
| 内容口径 | 涉及岗位评估维度/流程规则的问题，以 docs/API.md、docs/DATABASE.md、REPORT_TO_P2.md 为准 |
