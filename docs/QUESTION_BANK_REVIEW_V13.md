## 三、v13 发现的问题

### 1. 行为面试题题干内嵌「岗位软技能考察」标签（已由 P1 入库时自动处理 ✅）

45 题（3 岗 × 15 题行为面试）题干末尾嵌入了形如
`【岗位软技能考察：故障应急响应意识】` 的元信息——这是给面试官/评分模型看的，
但题干会直接读给候选人，不应暴露；且存在标签与题目内容不匹配的情况
（如「你如何看待加班？」也挂"故障应急响应意识"标签）。

**处理**：导入脚本已自动把标签从题干剥离，存入独立的 `soft_skill_tag` 列
（题库表 `questions`），题干保持纯净可直接读题。**建议 P5 后续版本把该标签
单独放一列**（如「考察软技能」），与题干分离，并在各题间做区分（当前 15 题
共用同一标签）。

### 2. 无 position_code 列（可选优化）

旧审查报告要求新增 `position_code` 列，v13 仍未提供，但「所属岗位」列（
Java后端 / Web前端 / 软件测试开发）齐全。P1 已按映射导入：

| 所属岗位（题库列） | position_code |
| :--- | :--- |
| Java后端 | backend |
| Web前端 | frontend |
| 软件测试开发 | test_engineer |

**建议**：后续版本若岗位清单变化，请把该列值直接改成 code，避免依赖映射。

### 3. 题目编号跨岗位重复（已知设计，P1 已处理）

每岗都有 tech_001~050 / scene_001~040 / code_001~025 / project_001~020 /
behavior_001~015。入库以 `(position_code, question_no)` 复合唯一键约束，
不冲突，无需修改。

### 4. 题目分类碎片化（可选优化）

部分「题目分类」只有 1 题，会稀释检索过滤效果：

- Java 后端 5 个：技术选型与方案 / 数据库架构实践 / 缓存架构实践 /
  分布式事务实践 / 分布式共识实践
- 软件测试 8 个：容器与云原生 / 微服务测试 / 移动端测试 / 全链路测试实践 /
  安全测试实践 / 端到端测试实践 / 可观测性实践 / 性能压测实践

**建议**：下次修订时把这些 1 题分类合并到上位分类
（如「分布式架构实践」「专项测试」），统计表同步更新。
