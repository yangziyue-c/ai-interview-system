# interviewer/ — P2（后端开发 B）面试官算法目录

> 本目录是 **P2 的算法执行版**，与 P3 的 `backend/evaluator/` 平级。
> **P2 修改算法只需要动本目录**（若需调整题库词表/模型字段，与主项目确认后同步改）。

## 一、目录内容

| 文件 | 职责 |
| :--- | :--- |
| `question_bank.py` | 题库策略核心：四段追问解析、笼统判断、开场/追问/换新/收尾选题、锚点层级推断 |

## 二、主项目如何调用本目录

主后端 [app/adapters/ai_interviewer.py](../app/adapters/ai_interviewer.py) 直接 import 本目录：

```
from interviewer import question_bank
```

出题数据源优先级：**题库策略（本目录）> AI_INTERVIEWER_URL > LLM 直连 > 内置 Mock**。
任一路径失败逐级降级，面试流程永不中断。

## 三、算法速览（改代码前先读）

策略唯一入口是 **`pick_next(db, position, round_no, history, is_follow_up)`**，
其内部先加载该岗位题目，再交给纯函数 `pick_next_from_questions` 决策
（解析与决策全部在同步纯函数中，可直接单测）。

1. **开场题（round=1）**：`pick_stage` 阶段=开场热身 且 难度=easy，随机抽
2. **追问（round=2~5）**：`find_anchor_question` 从 history 尾部找最近一条
   题库题干作「锚点」，锚点之后的追问次数 n 决定层级：
   - n=0 → L1：回答含触发关键词 → 对应追问；回答笼统 → l1_vague/降级追问；
     胜任但未命中关键词 → 换新题（降级策略只用于回答困难时）
   - n=1 → L2 递进追问；n=2 → L3 极限追问（回答笼统时落降级策略）
   - n>=3 或无锚点 → 换新题
3. **换新题**：最后两轮强制收尾交流；round>=3 深度考察（无则核心考察）；
   否则核心考察
4. **追问触发条件**：解析 `questions.follow_up_triggers` 字段的四段结构
   （【L1-触发追问】【L2-递进追问】【L3-极限追问】【降级策略】），
   解析器兼容全部真实行格式（挤行/无引号关键词/条件式/单行多子句/半角箭头），
   样本与措辞变体见 `backend/tests/test_question_bank.py`

## 四、修改注意事项（踩过的坑，均已有测试防回归）

- **锚点只做精确匹配**，不要加"包含匹配"：L1 追问文本常内嵌引用题干，
  包含匹配会把追问误判成新锚点，追问链断链。
- **段头只认行首**，不要用任意子串匹配：真实题库有内容行内嵌「降级策略」
  字样（如「…结合消息合并与降级策略，设计专项测试方案？」），子串匹配会把
  内容误切成段头。
- **L1 兜底行措辞多变**（若回答笼统/简洁/很浅显/偏理论化/只答理论缺乏实践…），
  解析时不枚举形容词，凡「若回答/若只答」开头的行都归 l1_vague。
- **L2/L3 行箭头后带引导词**（「→ 追问：」「→ 极限场景：/深度追问：」），
  必须剥离，否则脏前缀会读给候选人；但「追问」后无冒号时是文本本体，保留。
- **笼统判断不要用「简单/基本/大概」**（「简单工厂模式」「基本类型」会被误伤），
  也不要用裸「不会」（「不会产生脏读」是确定性否定而非露怯）。
- **最后两轮强制收尾**：真实题库每题都带非空追问计划，若不强制，追问链会
  延伸到最后一轮，收尾题永不出现（实证：修复前 0/2700 场模拟到过收尾）。
- 阶段词表（开场热身/核心考察/深度考察/收尾交流）与 difficulty（easy/medium/hard）
  从 `app/models/question.py` 的常量解包，单一来源自动跟随。
