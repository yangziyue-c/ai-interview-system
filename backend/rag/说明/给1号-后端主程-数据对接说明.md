## 二、主库字段（18 个，JSON 数组，UTF-8）



```
题目ID / 所属岗位 / 题型分类 / 难度等级 / 面试阶段 / 核心关键词 /

考点优先级 / 题目内容 / 基础得分点 / 进阶得分点 /

L1基础追问 / L2递进追问 / L3拓展追问 / 降级策略 /

建议用时(分) / 适用题型基准 / 单题校准锚点 / 关联知识点
```

**建表建议**：



* `题目ID` 为主键（格式如 `JAVA_BACKEND-Q0725`），**贯穿全链路**：RAG 检索命中 → 按原题 ID 回主库取完整素材 → 面试状态机记录当前题 ID → 评估按题 ID 查锚点。

* `关联知识点` 格式：`知识点ID|名称|学习建议`（换行分隔，可拆子表）。

* `单题校准锚点`：评分时判定 "技术水平 / 岗位匹配度" 的具体标准，评估模块用。

## 五、建议的 API 设计（供你封装，2 号会来调）



```
POST /rag/search

入参：{ "query": "学生回答或面试官问题", "job": "Java 后端开发工程师",

\&#x20;       "mode": "select | expand", "top": 3, "level": null }

出参：{ "results": \\\[ { "score": 0.997, "题目": "...", "参考答案": "...",

\&#x20;       "原题ID": "JAVA\\\_BACKEND-Q0725", "层级": "语义变体", "岗位": "...", ... } ] }

mode=select  → 按原题ID去重返回 Top-N 道不同题（出题）

mode=expand  → 命中最高分题后，按原题ID取该题全部层级片段（追问/评分）
```

**状态机对接建议**：面试轮次中保存 `current_question_id`（原题 ID），学生回答后调用 expand 模式取追问素材；评估时用 `current_question_id` 直查主库 18 字段。

## 六、现成代码（已跑通，可直接复用）

### 1. 现成 HTTP 服务（推荐，你几乎不用写代码）

服务已落地在项目内 `backend/rag/代码/`，由 `backend/start.py` 自动拉起：



```
cd backend\rag\代码

pip install -r ..\requirements-rag.txt     # 约 2.5GB（torch 走 CPU 索引）

python 05_rag_api_server.py                # 启动后监听 0.0.0.0:8003
```



* `POST /rag/search` — 入参 `{"query":"...","job":"Java 后端开发工程师","mode":"select|expand","top":3,"level":null}`；mode=select 返回 Top-N 道不同题，mode=expand 返回命中题全部层级片段（含 L1/L2/L3、得分点、降级策略）

* `GET /health` — 健康检查（返回 collection 总条数 74,011）

* `GET /question/{原题ID}` — 按原题 ID 返回主库 18 字段完整素材（未命中返回 404）

* 模型启动时加载一次：首次需下载约 4.5GB（走 hf-mirror 镜像），之后约 10-30 秒；CORS 已放开，4 号前端也可直接调

* 生产部署建议：用 uvicorn 多 worker 或放 Nginx 后面（检索本身无状态，可横向扩展）

> **端口是 8003 而非 8000**：本机 8000 被 Godot AI MCP 占用（项目铁律），
> 可用环境变量 `RAG_PORT` 覆盖。
